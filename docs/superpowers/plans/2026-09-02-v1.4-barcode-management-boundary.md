## Locked adapters (WS-001 ADR-001 / ADR-002)

Do this **before** Phase 1 copy. These two types from `84e905c` are **rejected**. Do not copy them.

### ADR-001 — `ProductImageResolver` REJECTED

```text
Status: REJECTED
Do not copy: modules/Product/src/Services/ProductImageResolver.php
```

Reason: one Product implementation file becomes a leak into Product expansion (presenters, DTOs, thumbnail policy).

Replacement, new file under Barcode only:

```text
BarcodeProductSearchService
  -> BarcodeImageResolver          (create in modules/Barcode)
       -> MediaQueryServiceInterface   (already on main)
```

Signature:

```php
resolve(?string $mediaUuid): ?string
```

Search reads `ProductMedia.media_uuid` (main has no `products.media_uuid`) and passes it in. The resolver must not take a `Product` model. Use `getUrl()` on main — do not copy archive `preload()` onto the Media contract.

See `docs/superpowers/specs/2026-09-02-barcode-product-consumer-contract.md`.

### ADR-002 — `SiteIdentityServiceInterface` REJECTED

```text
Status: REJECTED
Do not copy: Commerce\Contracts\Settings\SiteIdentityServiceInterface
Do not copy Footer v1 / Settings expansion from 84e905c
```

Reason: the interface is not on `main`. Barcode only needs an owner label.

Keep `BarcodeOwnerResolver` inside Barcode. Fallback chain on `main`:

```text
Seller.name  (if marketplace_sellers exists and product.seller_uuid is set)
  -> SettingQueryServiceInterface::get('store.name')   (already on main)
  -> config('app.name')
```

If Marketplace is disabled or `Seller` is unavailable: `store.name` then `config('app.name')`. Terminal presentation fallback: `'Store'`. Owner name is presentation data — never throw, never block queue or print.

Do not add a site-identity contract in v1.4.0.

### ADR-003 — Barcode is a Product consumer

```text
Status: LOCKED
Barcode depends on Product (narrow read).
Product never depends on Barcode.
```

Four IAM codes stay as-is. Treat as role packs only:

```text
Operator  barcode.print + barcode.history.view
Admin     barcode.template.manage + barcode.history.reprint
```

Search is the only Product query. Downstream uses `BarcodeSearchResult` then print-job JSON lines. Do not call Product/POS/Inventory services. Print payload is a label snapshot, not a Product catalog copy.

### ADR-004 — Print queue owns the label payload

```text
Status: LOCKED
Every print creates a barcode_print_jobs row first.
Templates and reprints use stored payload only.
```

Status vocabulary: `queued` | `printed` | `failed` (not `completed`). Reprint re-renders the same job UUID; do not clone the row or mutate payload. Do not re-query Product, Media, Marketplace, or Settings.

See `docs/superpowers/specs/2026-09-02-barcode-print-queue-contract.md`.

### ADR-005 — Test contract

```text
Status: LOCKED
PHPUnit only. No browser E2E in v1.4.
Tests must fail when ADR-001–004 are violated.
```

See `docs/superpowers/specs/2026-09-02-barcode-test-contract.md`.

### ADR-006 — Template is layout only

```text
Status: LOCKED
Templates define paper, grid, type, and field visibility.
No business logic, SQL, or Product/Media/Marketplace/Inventory/Scanner deps.
```

Four presets: `a4_40`, `a4_24`, `a4_65`, `thermal_50x30`. Catalog in config; archive columns stay. `paper_size` is derived from `preset_code`. Edit may change preset (overwrites frozen mm). Custom = preset + overrides. Jobs render from `job.settings` snapshot only. Print service outputs HTML/PDF only. No `paper_width_mm` on the table.

See `docs/superpowers/specs/2026-09-02-barcode-template-layout-contract.md`.

Run **Gate E immediately after the first path copy** (Phase 1), before wiring review. Run A–D again before merge.

After extraction:

```bash
find modules -maxdepth 1 -type d | sort
```

