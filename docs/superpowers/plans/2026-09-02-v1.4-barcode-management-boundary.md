## Acceptance gates

All four must pass before merge to `main`. A failed gate means the extraction is out of boundary, not “almost done”.

### Gate A — Module isolation

After extraction:

```bash
find modules -maxdepth 1 -type d | sort
```

The only **new** directory that came from `84e905c` must be:

```text
modules/Barcode
```

If `modules/WarehouseScanner` or `modules/Wishlist` (or any other module tree from `84e905c`) appears, the boundary is broken.

### Gate B — Storefront freeze

Before merge:

```bash
git diff main...feat/barcode-management-v1 -- resources/views/components/storefront
```

Must be:

```text
0 files changed
```

`resources/views/components/storefront/**` is frozen at v1.3.0 thin adapters.

### Gate C — Feature regression

On `feat/barcode-management-v1`, these suites must stay green:

```text
tests/Unit/Features/FeatureServiceTest.php
tests/Feature/Features/SystemFeatureAdminTest.php
tests/Feature/Features/EnsureFeatureEnabledTest.php
tests/Feature/Cms/CmsScheduledPublishingTest.php
tests/Feature/Cms/ScheduledPublishingFeatureFlagTest.php
tests/Feature/Cms/CmsBlogV1Test.php
tests/Feature/Cms/CmsAdminTest.php
```

Barcode must not regress v1.1 Feature Flags, v1.2 Scheduled Publishing, or v1.3 Blog UI.

### Gate D — No recovery merge

**No commit on `feat/barcode-management-v1` may come from:**

```bash
git merge feat/barcode-stock-recovery
git checkout 84e905c -- .
```

Files may enter the branch only by **path-by-path extraction** from `84e905c` (or equivalent: `git show 84e905c:path > path` / checkout of listed Include paths only).

`84e905c` is not v1.4.0.
