# v1.4.0 Barcode Management Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extract `modules/Barcode` onto current `main` as v1.4.0 Barcode Management, adapted to ADR-001–006, without merging `feat/barcode-stock-recovery`.

**Architecture:** Copy the Barcode module and kernel generator types path-by-path from archive `84e905c`, splice host wiring into current `main`, then rewrite search/owner/queue/template/print so Barcode is a Product consumer and a print-queue owner whose templates are preset layouts. Render HTML/PDF from `LabelPayload` + `job.settings` snapshot only.

**Tech Stack:** Laravel 13, PHP 8.4, PHPUnit 12, `picqer/php-barcode-generator`, `dompdf/dompdf`, Vite, existing IAM Module Management catalog.

## Global Constraints

- `84e905c` is a recovery archive, not a release candidate. Never `git merge feat/barcode-stock-recovery`. Never `git checkout 84e905c -- .`.
- Gate E allowlist is `docs/superpowers/plans/2026-09-02-v1.4-barcode-extraction-manifest.md`. Any extra path is a boundary break — stop and revert.
- ADR-001: do not copy `ProductImageResolver`. Create `BarcodeImageResolver::resolve(?string $mediaUuid): ?string` using `MediaQueryServiceInterface::getUrl()` (no `preload()`).
- ADR-002: do not copy `SiteIdentityServiceInterface`. Owner fallback is `Seller.name` → `SettingQueryServiceInterface::get('store.name')` → `config('app.name')` → `'Store'`. Never throw.
- ADR-003: Barcode depends on Product (narrow read). Product never depends on Barcode. Search is the only Product query. Four IAM codes unchanged.
- ADR-004: every print creates a `barcode_print_jobs` row first. Status ∈ `{queued, printed, failed}` (never `completed`). Reprint re-renders the same UUID from frozen payload + settings. Do not clone the row.
- ADR-006: `preset_code` is the source of truth. `paper_size` is derived from it. Manual `paper_size` / millimetre writes are forbidden. Edit may change `preset_code` and must overwrite frozen millimetre fields. Renderer reads `job.settings` only — never `barcode_templates`, never live catalog millimetres. Snapshot wins.
- Preset codes (underscores): `a4_40`, `a4_24`, `a4_65`, `thermal_50x30`. Default `a4_40`. Drop Thermal 40×30, `a5`, `custom`.
- `a4_40` is 4 columns × 10 rows. `labels_per_page = rows * columns`.
- No `paper_width_mm` column on `barcode_templates`. Those keys live on `ResolvedBarcodeLayout` and on `job.settings`.
- Print service outputs HTML and PDF only. No printer drivers.
- No browser E2E. PHPUnit only. Do not edit `resources/views/components/storefront/**`.
- Do not copy archive `composer.lock`, `config/admin.php`, or `DatabaseSeeder`.
- Core `packages/commerce/core/config/barcode.php` is **generation strategies**. Layout presets live in `modules/Barcode/config/barcode.php`. Do not mix those files.

/**

 * @return array<string, mixed>
 */
private function mergePreset(array $data, ?BarcodeTemplate $existing = null): array
{
    $code = (string) ($data['preset_code'] ?? $existing?->preset_code ?? 'a4_40');
    $preset = config("barcode.presets.{$code}");
    if (! is_array($preset)) {
